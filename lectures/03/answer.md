## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/tools.py` に `save_learning_log(topic: str, content: str)` を追加した。
  - `learning_log/` 内に UTC の作成日時・学習テーマ・学習内容を UTF-8 の JSON で保存する。ファイル名は日時と UUID からプログラム側で生成し、既存ファイルを上書きしない。
  - `app/agent.py` で `requires_approval=True` を指定して登録し、出力型に `DeferredToolRequests` を追加した。
  - CLI は保存内容を表示して `[y/N]` を確認する。`y`（大文字・前後の空白も可）のときだけ承認し、それ以外・空入力・EOF・Ctrl+C は拒否する。
  - 承認結果をツール呼び出し ID に対応づけた `DeferredToolResults` と、元の `message_history` を使って再開する。複数の保存要求も1件ずつ確認する。
- 結果：
  - `uv sync --frozen` で講座指定の依存関係を導入し、`uv run pytest -q` は **25 passed**。
  - `TestModel` を用いて承認前はディレクトリも作られないこと、承認後は確認した引数の内容が1件保存されることを確認した。
  - 拒否時は新規ファイルを作らず、既存ファイルの内容も変更しないことを確認した。
  - CLI の入口 `main()` から承認・拒否・空入力・不明な入力・EOF・Ctrl+C・`--trace` をテストした。
  - 日本語の保存、2回の保存で上書きされないこと、2件の要求を片方だけ承認した場合の保存件数も検証した。
  - ここでの検証は API キー不要の `TestModel` によるもの。Gemini 実モデルでの呼び出し結果は未記録。
- 気づき・疑問：
  - プロンプトに「確認する」と書くだけでなく、ツール登録時に承認を要求すると、ファイル保存前にプログラムとして実行を止められる。

### 実モデルでの確認コマンド

```bash
uv run python -m app.agent --list-tools
uv run python -m app.agent --trace "今日、LoRAは低ランク行列を使う手法だと学んだ。学習記録に保存して"
```

同じコマンドを2回実行し、1回目は `y`、2回目は `n` を入力する。
承認時だけ `learning_log/` に JSON が増えることを確認する。
個人の学習記録は既存の `.gitignore` で共有対象から除外されている。
